Monitoring too many talkgroups can overpopulate the node with reflector traffic, increase CPU activity, and make operation less predictable on smaller systems. Six monitored talkgroups is a practical upper limit.

Reflector TalkGroup behaviour
Use 0 for no default TalkGroup. A positive default TalkGroup is selected for local traffic when no other TalkGroup is active.

A non-zero default may take precedence over ordinary monitored TalkGroups. A monitored TalkGroup requires a higher priority using + or ++ where appropriate.
Seconds of inactivity before the selected TalkGroup is released. The dashboard default is 60 seconds.
Monitoring TalkGroups
Enter a positive TalkGroup number. Append + for increased priority or ++ for highest priority. Examples: 235, 23560+ and 23570++.

The same underlying TalkGroup must not be entered more than once, even with a different priority.
